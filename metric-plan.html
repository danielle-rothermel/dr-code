Metrics Extraction Module: Implementation Plan

dr-code · 2026-07-14
A new package, dr_code/metrics, implements metric-design: declared questions over trace-shaped input, one flat self-describing record per question — always, and a single engine that shares derived views, batches sandboxed execution behind the injectable SandboxRunner, and caches by content hash. The HumanEval responsibility split and runner injection have already landed. Builds on the implemented dr_code.trace boundary contract; independent of the preprocessing plan.

The HumanEval prerequisite is complete.

  • task.py owns task/evaluation models, best-function selection, and dataset parsing; it no longer owns test parsing or sandbox orchestration.
  • parsed_tests.py owns test parsing, while batch_runner.py owns execution payloads, sandbox calls, and outcome attribution.
  • run_subprocess_batch and evaluate_human_eval_code accept run_in_sandbox: SandboxRunner, so the metrics engine can reuse the existing seam.
  • The dependency-free runner is a real .py resource in sandbox_runner_script.py, loaded via importlib.resources.

Two operator kinds, one interface.

  • Pure operators (all but code_test) compute directly, drawing shared derived views from the ViewCache.
  • Execution-backed operators (code_test) declare ExecutionRequests in phase one; the engine runs them deduped and batched, then hands results back for phase-two computation.
  • Callers see neither difference — questions in, records out (X-M4).

Clusters split by question, not by payload.

  • The old payload families bundled for amortization; the engine's ViewCache + content-hash caching does that now (X-S4), so clustering buys no efficiency — it only costs granularity.
  • The test: a cluster is one metric only if you would never want part of its answer without the rest. So gen_stats splits into text_stats + code_leakage (distinct questions, distinct settings), parse_outcome leaves ast_stats (meaningful on unparsed text), and compression runs one codec + level per question.
  • Kept clusters: ast_stats (one walk) and code_test (one execution) — you can't take half.

The engine is two-phase: collect, then compute.

  • Bind: resolve operators, validate settings and trace keys/kinds — WiringError before any work (metric-design L2).
  • Phase 1: collect execution requests across all questions and all traces, dedupe by content-hash cache key (at-most-once).
  • Phase 2: compute each question; Absent input ⇒ not-applicable record, operator exception ⇒ operator-failure record (totality, L3).

Records are flat rows with a three-way status.

  • Every record carries metric identity + version + settings, lineage (on-key, producer id/version/hash), and one of: measured values, not-applicable with cause, or operator failure.
  • record_rows flattens to dataframe rows with metric-prefixed value columns — analysis tools need no system code (X-S3).
  • Not-applicable ≠ measured zero; the distinction is a status column, not a magic value.

Any producer's trace works; task context rides in the trace.

  • Input is a boundary Trace — fresh from preprocessing, deserialized, or built with external_trace; all three must produce equal records (X-S2).
  • code_test and ratio-bearing compression need task context: callers put the task in the namespace as a JsonArtifact; operators revalidate to HumanEvalTask at bind time.
  • Questions on input/output work with any producer; only intermediate measurements name step instances.

Caller policy stays outside; failure attribution splits three ways.

  • scoring.score_humaneval_submission becomes the example policy consumer: its outcome taxonomy derives from code_test records (S5). No thresholds, verdicts, or "best" in records (X-M3).
  • Attribution: candidate-attributable outcomes (kill returncodes, output floods, timeouts) are data in values; operator bugs are operator-failure records; infrastructure breakage (SandboxError, harness errors) raises — operators can still alert on it, matching today's EvaluationHarnessError policy.

class MetricOperator:
    NAME: ClassVar[MetricName]
    VERSION: ClassVar[str]        # semantics version: changing computation bumps it (X-M2)
    INPUT: ClassVar[ArtifactKind] # required kind for the `on` key; mismatch => WiringError
    Settings: ClassVar[type[OperatorSettings]] = OperatorSettings

    def __init__(self, settings: OperatorSettings) -> None: ...

    def auxiliary_keys(self) -> tuple[str, ...]:
        """Extra trace keys this operator reads (e.g. code_test's task key).
        Validated at bind time like `on`; Absent aux values also yield
        not-applicable records.
        """
        return ()

    def execution_requests(
        self, value: Artifact, aux: Mapping[str, Artifact]
    ) -> tuple[ExecutionRequest, ...]:
        """Phase 1: declare sandboxed work. Pure operators return () (default)."""
        return ()

    def compute(
        self, value: Artifact, aux: Mapping[str, Artifact], ctx: EngineContext
    ) -> dict[str, MetricScalar]:
        """Phase 2: pure computation from canonical artifacts, shared views
        (ctx.views), and resolved execution outcomes (ctx.outcome_for).
        Facts only — counts, ratios, outcomes; no verdicts (X-M3). Results may
        not depend on caches, scheduling, or trace freshness (L2).
        """
        raise NotImplementedError

class CompressedLengthSettings(OperatorSettings):
    # One codec + level per question: independent parameterizations are
    # independent questions. Both fields required — the current code relies on
    # implicit library defaults (ZstdCompressor() ⇒ level 3, gzip.compress ⇒
    # level 9), which could drift semantics without a version bump (X-M2);
    # migrated definitions pin those values explicitly.
    method: CompressionMethod
    level: int                          # gzip: 0–9; zstd: 1–22 (negative fast levels valid)
    reference_key: str | None = None    # trace key holding reference Code for ratio values


class CompressedLength(MetricOperator):
    """Ports humaneval/compression.py, one codec per question. Values:
    compressed_bytes, representation_bytes; plus ratio_to_reference /
    percent_reduction when reference_key is declared (today's ground-truth
    denominator, made explicit). Empty reference keeps ratio None — existing
    behavior. The compressor is constructed from settings, replacing the
    module-level ZSTD_COMPRESSOR singleton.
    """
    NAME = MetricName.COMPRESSED_LENGTH
    VERSION = "1"                       # bump alongside codec-library upgrades: sizes at
                                        # a fixed level may drift across zstd/zlib versions
    INPUT = ArtifactKind.TEXT           # accepts TEXT or CODE (both carry text)

Implementation order & considerations

#DeliverableContentsProof it works
1Skeleton + first pure operator names, records, definition, registry, operators/base, engine bind path (no execution), text_stats. Totality test (N questions ⇒ N records incl. Absent + operator-failure paths); WiringError tests; parity vs text_metrics outputs.
2Remaining pure operators code_leakage, parse_outcome, ast_stats, compressed_length; move compression.py; ViewCache. Field-for-field parity vs build_metrics_payload stages on the HumanEval+ snapshot, values re-keyed across the six-operator layout; pinned-level questions reproduce today's implicit-default compressed sizes exactly.
3Execution path + code_test engine/execution.py, code_test on batch_runner. With a local test runner: case counts match evaluate_human_eval_code on snapshot tasks; candidate-kill/output-flood/timeout attribution preserved; SandboxError still raises.
4Batching + engine promises extract_metrics_batch, InMemoryExecutionCache. At-most-once via counting fake runner; determinism: fresh trace ≡ deserialized trace ≡ external trace record equality; dataframe round-trip of record_rows.
5Caller-policy example + migration Derive SubmissionOutcome-equivalent scoring from records; migrate callers; retire humaneval/metrics.py. Outcome parity vs score_humaneval_submission across the snapshot; then one coordinated breaking change removes the old payload path.

Migration is a clean break, staged by parity.

  • humaneval/metrics.py keeps working untouched through steps 1–4; operators port the pure functions, they don't wrap the old module.
  • Once parity tests hold, one coordinated change moves profiles.py, the public façade, tests, and direct payload callers, then deletes the old path — no aliases or shims.
  • metric_models.py payload shapes inform record value keys but are not preserved as API.

Batching depth is deliberately staged.

  • v1 "batching" = request-level dedupe + sequential execution; that alone delivers at-most-once and cross-trace reuse.
  • One-runner-session-per-batch (design L3, "where possible") needs sandbox work — today each invocation is one container. Defer behind run_requests, whose interface already permits it.
  • Persistent cross-run cache is likewise deferred behind the ExecutionCache protocol.

Settings-as-dicts: same trade as preprocessing.

  • MetricQuestion.settings stays a JSON dict for serializable, hashable definitions; bind-time validation against operator Settings raises WiringError.
  • Settings participate in record identity and cache keys — two questions differing only in settings are distinct questions.

Record width and naming need one early decision.

  • ast_stats emits ~30 values; with the "{metric}.{key}" prefix convention, columns stay collision-free and self-describing.
  • Multi-question dataframes are sparse by design (one record per question, different value sets); consumers pivot on metric + on_key.
  • Lock the convention in record_rows tests during step 1 — renaming columns later breaks comparability (X-M1).

Determinism has two soft spots: timing and codec drift.

  • Runner case outputs include elapsed_seconds; identical inputs won't reproduce it exactly. Decision: keep timing out of v1 record values (or mark it explicitly non-comparable) so the determinism promise — same inputs + identity ⇒ same record — holds testably.
  • Cache hits returning stored outcomes make this visible: a cached record must equal a fresh one.
  • Codec drift: compressed sizes at a fixed level are not guaranteed stable across compressor library versions. Levels are pinned in settings, dependencies are locked in uv.lock, and a zstandard/zlib upgrade pairs with a compressed_length VERSION bump (X-M2).

Known risks.

  • Current-contract preservation: the engine must reuse batch_runner.py's sandbox attribution and preserve scoring.py's outcome semantics; focused parity tests and the full suite gate the migration.
  • JsonArtifact task payloads: HumanEvalTask revalidation re-runs its parse-on-validate model validator; verify round-trip model_dump/validate is lossless before relying on it (add a test in step 3).
  • Best-function loop moves: today evaluate_human_eval_code loops function names then picks best; code_test must preserve per-function request fan-out or counts drift — the step-3 parity test is the guard.
