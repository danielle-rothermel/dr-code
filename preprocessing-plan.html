Preprocessing Module: Implementation Plan

dr-code · 2026-07-14
A new package, dr_code/preprocessing, rebuilds the extraction pipeline from preprocessing-design as atomic, declared steps over typed artifacts — one operation per step, so definitions choose exactly which operations run — mirroring the synthetic corruption architecture. Where first-success semantics forbid splitting (the extraction ladder), the constituents become an ordered strategy tuple in settings instead. The core grid (text_transforms, text_analysis, code_analysis, import_inference) is reused as-is as step bodies; code_extraction/code_parsing keep serving /explain until a parity harness proves the new pipeline equivalent, then become the migration target. Depends on the boundary contract package.

Steps are thin adapters; the core grid stays put.

  • text_transforms, text_analysis, code_analysis, import_inference already are total, deterministic functions — exactly what step bodies need.
  • Steps wrap, never reimplement: parse the artifact, call the function, wrap the result. New logic in a step is a smell.
  • Existing unit tests for those modules keep their value untouched.

Every constituent operation is its own step.

  • Today's bundles unbundle: normalize_text becomes six atomic text steps, infer_necessary_imports becomes three import steps — definitions include, exclude, and reorder each operation individually.
  • No inclusion flags: a boolean per sub-operation hides 2n pipeline variants inside settings; an explicit step list keeps the definition self-describing at a glance (P-S3) and lets facts attribute which operation changed the text.
  • Grouping happens in definitions, not steps; a unit test pins composed-atomics ≡ normalize_text.

The ladder's granularity is an ordered strategy tuple.

  • extract_candidates cannot split into pipeline steps — its constituents are first-success alternatives, not a sequence, and fallbacks must stay inside one step (P-L2).
  • So the choice becomes data: settings hold an ordered tuple[ExtractionStrategy, ...] — include, exclude, and reorder per definition.
  • New strategies are additive: enum member + registered callable, guarded by the same sync-test pattern as the step registry.
  • v1 compat = the tuple without escaped_python, replacing the earlier boolean setting.

Failures become Absent; the runner always completes.

  • A step that cannot proceed without guessing raises StepFailedError(cause); the runner converts it to Absent with cause (P-M2).
  • Downstream steps skip and record propagation; the pipeline finishes with a full trace every time (P-S4).
  • An empty candidate set is data, not a failure — the absence surfaces where cardinality is fixed, at select_first.

The corruption architecture is copied deliberately.

  • Same shape as synthetic/corruptions: uniform base class, one file per step, name-keyed REGISTRY, frozen definitions, single fold runner.
  • Reuse the registry↔enum sync test verbatim so the step vocabulary cannot drift (P-L3).
  • One difference: steps take no rng — determinism is settings + input only.

Old provenance tree is replaced, not ported.

  • ExtractionTraceNode's decision tree is the shape design-review findings #3 and #5 flagged as fragile de-facto contract.
  • The new trace is flatter: values per instance name + step facts (chosen alternative, rejection reasons, candidate counts).
  • /explain and the viewer keep consuming the old shape until migration (out of scope here); the parity harness compares outputs, not traces.

Out of bounds for this module.

  • Quality-based selection — cross-candidate preference belongs to caller policy over metric records (S5).
  • Scoring and outcomes — scoring.py is untouched by this plan.
  • Adaptive behavior — no settings change based on input shape; alternatives ladders are the only fallback mechanism.

src/dr_code/preprocessing/steps/base.pythe step contract
class StepSettings(FrozenModel):
    """Base for per-step settings; each Step subclass declares its own subclass."""


class StepFailedError(Exception):
    """Data failure: the step cannot produce output without guessing (P-M2).
    Converted to Absent-with-cause by the runner; never escapes run_preprocessing.
    """
    def __init__(self, cause: str) -> None: ...


@dataclass(frozen=True, slots=True)
class StepOutput:
    value: Artifact
    facts: Mapping[str, str] = field(default_factory=dict)
    # facts describe the output (chosen alternative, rejection reasons); a step
    # may describe, never prefer (P-L2)


class Step:
    NAME: ClassVar[StepName]
    VERSION: ClassVar[str]
    INPUT: ClassVar[ArtifactKind]     # composition determines pipeline shape (P-S1)
    OUTPUT: ClassVar[ArtifactKind]
    Settings: ClassVar[type[StepSettings]] = StepSettings

    def __init__(self, settings: StepSettings) -> None: ...

    def apply(self, value: Artifact) -> StepOutput:
        """Deterministic: same settings + input => same output.
        No RNG, ambient state, or clocks (P-L3).
        """
        raise NotImplementedError


class CandidateMapStep(Step):
    """Elementwise CandidateSet -> CandidateSet; fan-out stays data (P-S2).
    apply() maps over candidates in order, flattening list results in place so
    splits (e.g. name-guard) preserve relative candidate order.
    """
    INPUT = OUTPUT = ArtifactKind.CODE_CANDIDATE_SET

    def apply_to_candidate(self, source: str) -> str | list[str]:
        raise NotImplementedError


class AlternativesStep(Step):
    """Ordered first-success ladder inside one step — never pipeline branches (P-L2).
    apply() tries alternatives conservative-first; the winner's name is recorded
    as facts["alternative"]; all-fail raises StepFailedError.
    """
    def alternatives(self) -> tuple[tuple[str, Callable[[Artifact], Artifact | None]], ...]:
        raise NotImplementedError

class ExtractionStrategy(StrEnum):
    """The ladder's constituents, individually selectable per definition."""
    FENCED_BLOCKS = "fenced_blocks"        # text_analysis.candidate_blocks
    MARKDOWN_WRAPPER = "markdown_wrapper"  # strip_markdown_wrappers per block, re-split
    ESCAPED_PYTHON = "escaped_python"      # recover_escaped_python, then re-extract
    # future strategies are additive: enum member + STRATEGY_REGISTRY entry


# one callable per strategy: (text: str) -> CodeCandidateSetArtifact | None
STRATEGY_REGISTRY: dict[str, ExtractionStrategyFn] = { ... }
# sync test: set(STRATEGY_REGISTRY) == {s.value for s in ExtractionStrategy}

class ExtractCandidatesSettings(StepSettings):
    # ordered, first-success, conservative-first by the definition author's choice;
    # the tuple is part of definition identity (M2) — reordering is a new definition
    alternatives: tuple[ExtractionStrategy, ...] = DEFAULT_STRATEGIES


class ExtractCandidates(AlternativesStep):
    NAME = StepName.EXTRACT_CANDIDATES
    VERSION = "1"
    INPUT = ArtifactKind.TEXT
    OUTPUT = ArtifactKind.CODE_CANDIDATE_SET
    Settings = ExtractCandidatesSettings

    def alternatives(self):
        """Resolves settings.alternatives through STRATEGY_REGISTRY, in order.
        First strategy returning a non-empty candidate set wins; its name is
        recorded as facts["alternative"]. All-fail raises StepFailedError.
        The ladder stays inside this one step (P-L2); which rungs exist is data.
        """

src/dr_code/preprocessing/runner.pybind-time wiring, run-time data
@dataclass(frozen=True, slots=True)
class BoundStep:
    instance_name: str
    step: Step


def bind_definition(definition: PreprocessingDefinition) -> tuple[BoundStep, ...]:
    """Resolve each StepSpec in REGISTRY, validate settings via Step.Settings,
    and chain INPUT/OUTPUT kinds across the sequence. Any mismatch raises
    WiringError before any input is processed — incompatible definitions are
    wiring bugs, not data (eval-flow L2).
    """


def run_preprocessing(
    definition: PreprocessingDefinition, input_value: Artifact
) -> Trace:
    """Single mechanical fold, like synthetic's apply_recipe:

      value = input_value
      for bound in bind_definition(definition):
          value or Absent -> run step / skip-and-propagate
          record value under bound.instance_name; merge facts into step_facts

    StepFailedError -> Absent(failed_step=instance_name, cause); downstream
    steps record the same Absent with propagated_through extended. Always
    completes: trace has input, one value per instance name, and output —
    every intermediate is retained for later measurement (P-S4).
    Producer stamp: TraceProducer(definition_id, version, definition_hash).
    """

Parity is behavioral, not trace-shaped.

  • The harness compares outputs and absence causes, never the old ExtractionTraceNode tree — asserting internal decision-tree shapes is what P-L3 forbids and finding #3 flagged.
  • Facts that matter downstream (chosen alternative, candidate counts) get their own assertions as the new stable surface.

Old pipeline retires in a later, separate change.

  • code_extraction/code_parsing keep serving /explain, the viewer, and scoring.py until parity holds and metrics consume traces.
  • Then one clean breaking change swaps consumers and deletes the old modules — no long-lived dual paths.
  • The exported humaneval.__all__ is test-enforced; update façade and test together.

Semantics preserved from today's pipeline.

  • Empty input: extract fails ⇒ Absent("no candidates") — scoring's EMPTY_SUBMISSION maps from the cause later.
  • split_on_name_guard may multiply candidates; splits are inserted in place so conservative-first order survives.
  • dedent stays a step but is omitted from default definitions (today's apply_dedent=False).
  • Import handling mutates candidates — as three explicit steps, definitions that dedupe without inferring, or skip repair entirely, exist for measurement.

Settings stay dicts, validated at bind time.

  • StepSpec.settings: dict[str, JsonValue] keeps definitions serializable without a discriminated settings union per step.
  • The cost — no static settings typing — is paid back by bind-time validation against Step.Settings raising WiringError.
  • If settings grow complex, a typed union is a versioned definition change, decided then.

Corruption recipes become the standing adversarial corpus.

  • Every recovery step should name the corruption recipes that exercise it (fences ↔ add_code_fences, smart quotes ↔ add_smart_quotes, …).
  • Gap check while wiring the round-trip suite: recovery steps without a matching corruption get one added to synthetic/corruptions (P-L2).

Known risks.

  • Ordering drift: today fence-stripping happens per-candidate after block splitting; the parity harness is the guard that decomposition didn't reorder semantics.
  • Facts volume: per-candidate rejection facts can be large; cap stored source excerpts the way the runner script clips reprs (8000 chars) if traces bloat.
  • Intermediate volume: ~17 atomic steps each retain a full text value (P-S4); if serialized traces bloat, dedupe identical consecutive values by reference at serialization time — lossless, so still within S3.
  • Coverage gap inherited: code_parsing has no dedicated test file today; the parity harness + step tests become its effective regression suite before deletion.
