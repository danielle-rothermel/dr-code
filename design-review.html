Codebase Design Review

dr-code · 2026-07-13

Verdict: strong adherence, with the violations concentrated in one module and its tests

The repo has deep pure-function modules, a 22-adapter corruption seam, a deep sandbox, thin adapters, curated public surfaces, and an acyclic dependency graph. Most problems center on humaneval/task.py: four responsibilities in 1,026 lines, a monkeypatched sandbox dependency, and tests coupled to implementation details.

The measuring stick

Module
anything with an interface and an implementation — function, class, package, or slice
Interface
everything a caller must know: signature plus invariants, ordering, error modes, config
Depth
behaviour a caller can exercise per unit of interface learned
Seam
where behaviour can be altered without editing in place — where the interface lives
Port
dependency-facing interface at a seam; adapters are injected to satisfy it
Adapter
a concrete thing filling a slot at a seam — role, not substance
Leverage
callers: one implementation pays back across N call sites and M tests
Locality
maintainers: change, bugs, and verification concentrate in one place
Depth belongs to the interface. A module earns its place when deleting it moves complexity to callers. Tests should use the public seam. Two adapters prove a seam is real.

Deep modules hide complexity behind small interfaces.

small interface
lots of hidden behaviour
Deep — e.g. run_python_in_sandbox: 3 kwargs fronting ~300 LOC of container hardening
large interface — many methods, complex params
thin body
Shallow — e.g. for_loop_names: a tuple-of-strings contract as complex as its body

Core library grid

The four core modules form a deliberate 2×2 grid. The text_* layer is total: it never raises on bad input. The code_* layer requires valid Python and raises SyntaxError. Docstrings state this contract; property tests enforce it.

recover_escaped_python exposes str → str | None over ~130 private lines. code_analysis is a shared AST vocabulary, not a grab-bag. code_transforms provides string and tree APIs for distinct callers.

Coupling is thin and one-directional. The one runtime cross-edge is a documented deferred import. The text and code halves do not duplicate logic.

src/dr_code/__init__.py is empty, leaving submodule namespacing implicit. Add a docstring or a minimal curated surface.

synthetic/corruptions/base.pylines 12–29 · the port
class Corruption:
    """Base class for synthetic corruptions.

    Subclasses must declare:
        NAME: the CorruptionName they implement.

    The `apply()` method takes the original ground-truth source and a
    `random.Random` instance (seeded by the dataset builder) and returns a
    `CorruptedSample`.

    Implementations must be deterministic given the rng: same source + same
    rng state -> same output.
    """

    NAME: ClassVar[CorruptionName]

    def apply(self, source: str, rng: random.Random) -> CorruptedSample:
        raise NotImplementedError

Determinism is part of the interface. One gap: the plain base class delays a missing apply failure until call time; abc.ABC would fail at instantiation.

synthetic/dataset_builder.pylines 64–81 · accepts dependencies, doesn't create them
def build_dataset(
    tasks: Iterable[HumanEvalPlusTask] | None = None,
    recipes: Iterable[Recipe] = RECIPES,
    seed: int = 0,
    prefer_snapshot: bool = True,
) -> list[SyntheticSample]:
    """Build the full dataset list (in-memory).

    If `tasks` is None, load HumanEvalPlus through the explicit
    `prefer_snapshot` source choice.
    """
    if tasks is None:

            prefer_snapshot=prefer_snapshot

The small surface hides seed derivation, docstring stripping, RNG threading, dataset expansion, and JSONL serialization. Tests inject tasks= without network access. The CLI stays thin.

Small adapters are an acceptable uniformity cost. Manual enum/registry/recipe registration is test-guarded. load_humaneval_plus hardcodes I/O, forcing tests to monkeypatch private loaders, but correctly refuses silent fallback to stale snapshots.

humaneval/

humaneval is acyclic, with task.py as its oversized hub.

The sandbox hides security mechanics behind three inputs.

humaneval/sandbox.pylines 62–84 · 3 kwargs fronting ~300 LOC
def run_python_in_sandbox(
    *,
    source: str,
    input_json: str,
    timeout_seconds: float,
) -> SandboxCompletedProcess:
    """Run Python in a locked-down OCI container using bounded JSON IPC.

    The runtime and image are trusted deployment dependencies. The image must
    already exist locally: scored code can never trigger a registry pull.
    """
    payload = input_json.encode("utf-8")
    if len(payload) > MAX_SANDBOX_INPUT_BYTES:
        raise SandboxError(
            f"sandbox input exceeded {MAX_SANDBOX_INPUT_BYTES} bytes"
        )
    if timeout_seconds <= 0 or not math.isfinite(timeout_seconds):
        raise SandboxError("sandbox timeout must be finite and positive")

    runtime = _resolve_runtime()
    image = os.environ.get("DR_CODE_SANDBOX_IMAGE", SANDBOX_IMAGE)
    _validate_image_reference(image)
    _require_local_image(runtime, image)
    ...

Three parameters hide runtime and image validation, locked-down execution, bounded IPC, deadlines, forced teardown, and credential scrubbing. Private helpers and typed errors keep mechanics local while exposing failure modes.

scoring.py is equally deep: four arguments return CompletedScore | HarnessFailure, mapping every failure to a pure typed result.

humaneval/parsed_tests.pylines 311–326 · interface as complex as the body
def for_loop_names(loop_node: ast.For) -> tuple[str | None, str, str]:
    target = loop_node.target
    if (
        isinstance(target, ast.Tuple)
        and len(target.elts) == PAIR_TARGET_SIZE
        and isinstance(target.elts[0], ast.Name)
        and isinstance(target.elts[1], ast.Tuple)
        and len(target.elts[1].elts) == PAIR_TARGET_SIZE
        and isinstance(target.elts[1].elts[0], ast.Name)
        and isinstance(target.elts[1].elts[1], ast.Name)
    ):
        return (
            target.elts[0].id,
            target.elts[1].elts[0].id,
            target.elts[1].elts[1].id,
        )

The models are deep, but about eight public AST helpers have one caller each, loose tuple contracts, and no __all__. Their interfaces cost as much to learn as their bodies.

CodeExtractionResult.trace mirrors the pipeline, but is also persisted, returned by POST /explain, and rendered by the viewer. Its shape is a product contract, so pipeline refactors are interface changes. Internal tests should not casually pin node names.

serve/ & viewer/

HTTP handlers delegate all domain logic.

serve/app.pylines 65–74 · unpack → one call → error map
@app.post("/explain", response_model=ExtractionTrace)
def explain(request: ExplainRequest) -> ExtractionTrace:
    try:
        return explain_extraction(
            request.text,
            profile_id=request.profile_id,
            parser_version=request.parser_version,
        )
    except ValueError as exc:
        raise HTTPException(status_code=422, detail=str(exc)) from exc

Handlers contain no parsing or business logic. create_app() enables isolated tests; CORS is localhost-only; requests reject extra fields. The API returns the library's ExtractionTrace, and serve/__init__.py exports only two names.

serve/explain.py adds almost no behavior.
